Loopiter is an MIT-licensed SDK that coordinates feedback-driven AI
improvements. It is not an LLM, trainer, hosted observability service or rollout daemon.
The **0.3 alpha** (`0.3.0-alpha.1` on npm; `0.3.0a1` on PyPI) adds
[opt-in autonomous improvement](/closing-the-loop/opt-in-autonomous-improvement) in both SDKs.
Autonomy remains disabled by default. Start with the native, async **Python 3.11+ SDK**:
capture predictions and verified corrections, evaluate proposed changes, and deploy
through your own application adapters. The core has **zero runtime dependencies**
and no telemetry; PostgreSQL support is optional. No Node.js installation is needed
to use the Python package. Formerly Feloop.

These docs are Python-first. Follow the [Python quickstart](/get-started/python-quickstart)
to install and capture feedback, then the
[Python autonomous workflow guide](/get-started/autonomous-improvement-in-python)
when you are ready to configure bounded improvement. The separate Node.js ESM SDK
supports Node.js 22 and 24, also without core runtime dependencies.

Use the **Python** and **Node.js** tabs at the top of the docs to switch SDK guides.
Both packages are named `loopiter`, but npm and PyPI distribute separate SDKs.

The useful loop is:

**Capture → verified feedback → recurring scored segments → proposal → independent
evaluation → approval → deployment receipt → recovery or rollback.**

Capturing messages alone does not create trustworthy training labels. Applications
provide verified corrections or outcomes, define scores and write proposal/evaluation
callbacks. Loopiter stores evidence, bounds orchestration and protects lifecycle transitions.

## What ships

- Namespace-bound capture with validated JSON, insert-only creation and revision updates.
- Structured segment analysis that counts episodes as units where available, supports
  delayed outcomes and reports evidence counts/descriptive effects, not certainty.
- Immutable candidate content/evidence hashes; evaluations with dataset/evaluator
  versions; approvals tied to the exact latest passing evaluation.
- Durable deployment attempts, target reservations, receipts, inspect/reconcile and
  explicit predecessor-based rollback through your deployment adapter.
- Node store v3 / Python store v2 contracts, optional PostgreSQL 16/17 reference adapters and conformance suites.
- Review-first defaults with explicitly enabled prompt/routing autonomy, independent audit,
  production observation and automatic rollback through application adapters.
- Native Python and Node.js autonomous workflow examples, plus offline fixtures.
- A separate Node.js reviewed support-intent CLI with PostgreSQL and OpenAI/Azure integration.

## What does not ship

No hosted service, dashboard, auth server, billing, distributed scheduling, training
jobs, automatic fine-tuning, unrestricted code execution
or universal self-improvement. Other target kinds can be represented and evaluated;
their optimization and deployment require application adapters.

## Your first Python integration

1. Follow the [Python quickstart](/get-started/python-quickstart) to install the package,
   run a simulated example, and record your first prediction and correction.
2. Connect your database using the quickstart's PostgreSQL instructions. In-memory
   stores are development tools, not durable production storage.
3. Follow the [integration walkthrough](/get-started/integrate-an-improvement-workflow)
   to define trusted feedback, dataset partitions, an objective and application adapters.
4. Start in reviewed or experiment mode. Enable autonomous changes only with
   `self_improving=True`, `mode="autonomous"` and a complete validated policy.
5. Read [operations and recovery](/operate/autonomous-operations-and-recovery)
   before scheduling repeated ticks or connecting real traffic.

Use the [Python API reference](/reference/python-api) for method signatures and
the [Python examples](/get-started/python-examples) for runnable workflows.
For JavaScript or TypeScript, start with the [Node.js quickstart](/get-started/quickstart).
An alpha narrows support, not correctness obligations.
The supplied small fixture dataset is not evidence of production accuracy or revenue.
