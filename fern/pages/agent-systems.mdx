---
title: Agent systems
---

An agent can record its turns, tool calls and outcomes using the same contracts as
any ML application. Group a multi-step task into an episode, link child executions,
and record prompt/model/tool/workflow versions. Attach verified task outcomes rather
than assuming successful tool execution means the overall user goal succeeded.

Repeated scored failure segments can inform application-written recipes for routing,
prompt instructions or tool schemas. Loopiter does not automatically discover new
tools, spawn agents, edit code, scale workers or identify causal bottlenecks from
arbitrary logs. Code, capacity and agent_topology are candidate categories only.

Start with a reviewed recommendation. Independently evaluate the changed behavior
against representative complete tasks, not just individual tool calls; correlated
steps in one episode must not become many independent samples. Limit model calls,
latency, cost and privileges in the agent's own execution layer.

Only explicitly allowed prompt/routing targets can be enabled for autonomous
execution, with a complete policy and adapters supporting inspection and real rollback. Applying
a prompt change to an agent with privileged tools may not actually be low risk:
the recipe author and application policy must make that decision honestly.

No distributed scheduler, agent runtime or isolation layer is supplied. A library
can coordinate a well-specified improvement loop without becoming a platform for
unrestricted self-modifying agents.
