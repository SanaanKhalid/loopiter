---
title: Operating the alpha
---

This alpha supports Node 22/24, Python 3.11–3.14, and PostgreSQL 16/17 reference adapters. Use a
customer-owned database and a tested deployment adapter; development JSON/memory
stores are not a production durability story. The Node package is ESM and not intended
for browsers, edge runtimes or untrusted plugins running in the same process.

For per-state diagnosis, scheduling in both languages, budget interpretation and
step-by-step incident handling, use the
[autonomous operations runbook](/operate/autonomous-operations-and-recovery).

## Before enabling writes

Review and explicitly run SQL migrations. Configure authorization, redaction,
payload/query limits, source verification, least-privilege credentials, TLS and backups.
Keep model calls and deployments outside database transactions. Do not reuse one
namespace for unrelated tenants or mix synthetic and real evidence in the same cohort.

Start in recommend mode. Freeze a held-out dataset and independent evaluation gates.
Review the actual diff, evidence counts, model/prompt/dataset versions and evaluation
report. Human approval is an application authorization decision; the SDK records the
actor and exact passing evaluation, not the actor's real-world identity.

## Day-to-day operation

The application invokes the controller and owns scheduling. Page `events` for
candidate.created/evaluated/approved/rejected and deployment.pending/succeeded/not_applied
events. Forward structured controller blocked reasons to your logger. Events are
durable records, not a guaranteed push-delivery service. Maintain your own event
consumer checkpoint/idempotency and monitoring.

Alert on pending attempts, failed gates, sustained database errors, provider refusals,
budget exhaustion and drift in the serving version. Disable new deployments during
incidents while retaining inspection/rollback capability. An unknown inspection can
remain blocked indefinitely until authoritative external evidence is available.

Bound analysis with windows and maximumRecords. Dimension depth is at most two and
the default query cap is 20,000 per collection. The fixed synthetic benchmark records
elapsed time and memory for one local dataset; it is not a throughput guarantee.
Measure your database, concurrency, payload size and latency before expanding limits.

## Release gates

CI checks the SDK, store conformance, independent-process PostgreSQL races, fault
injection, simulated starter, actual npm tarball installation, runnable docs, Fern,
website type/lint/build and dependency audits. Node 22/24 × PostgreSQL 16/17 form the
supported test matrix. Missing database credentials skip local PG tests; dedicated
CI jobs configure a disposable database and must not skip them.

Before release, explicitly enable and retain one **live-model** smoke report. Fixtures
cannot substitute for missing credentials. No candidate passing is valid; fabricated
improvement is not. Confirm npm identity/name rights, MIT contents, private security
reporting, intended GitHub/website visibility and the `alpha` tag separately.
Actual npm publication, repository visibility changes, Fern/website publication and
release announcements are intentional release actions, not test side effects.
