---
title: Common pitfalls and FAQ
---

### Does Loopiter improve any model automatically?

No. It coordinates evidence and application-written proposals/evaluators/adapters.
The included starter demonstrates one classification prompt workflow. Other tasks
need trustworthy feedback and task-specific evaluation. Fine-tuning is not supplied.

### Is it still lightweight?

Yes: the Node SDK core has no runtime dependencies, service, daemon or required
provider. PostgreSQL and the OpenAI starter are optional imports/source examples.
Reliability metadata and tests do not turn it into a hosted platform.

### Can I feed operator messages directly into training?

You can capture them if authorized, but rephrasing is not a verified correction.
Define consent, redaction, source authority and label resolution first. Several
turns with one outcome are one episode unit, not independent training examples.

### Why did my findings disappear or a candidate fail?

Check window attribution, signal name/kind/score, positive weights, episode counts,
recurrence and entity thresholds. A positive effect threshold cannot pass without
an effect. Query overflow throws instead of silently truncating. A failed held-out
evaluation is expected and must not be rewritten as a success.

### Does recommend mode deploy? Is experiment sandboxed?

Recommend stores proposals only. Experiment evaluates without automatic deployment,
but callbacks are ordinary code in your process. Autonomous mode requires the explicit
self-improvement flag, an exact prompt/routing policy, independent audit, budgets and
observation/rollback adapters. The old experimental apply mode is rejected.

### A deploy timed out. Should I retry?

Reconcile the saved attempt first. Apply may already have happened. The target remains
reserved until authoritative inspect reports applied with a receipt or fenced
not_applied. Unknown must remain pending. Never delete the reservation to force a retry.

### Do namespaces make this a secure multi-tenant server?

No. They scope integrity operations. Your service still authenticates and authorizes
access, verifies labels and protects the database. Direct database access bypasses
application-level protections.

### Can I reuse old JSON deployment state?

Import it explicitly into historical records using a new destination. Preserve the
original file. Missing predecessors cannot honestly become an active rollback chain.
Re-evaluate and approve fresh candidates against an explicit serving baseline.

### Is the alpha already published or the website public?

Install `loopiter@0.3.0-alpha.1` or follow `loopiter@alpha` on npm.
The GitHub repository is public and private vulnerability reporting
is enabled. The canonical Fern documentation is published. The landing website has
its own deployment lifecycle; an npm release does not redeploy it.
