The package's generated declarations are the precise source of type signatures.
Import core types/classes from `loopiter`, database helpers from `loopiter/postgres`,
and conformance tests from `loopiter/testing`. Core never imports the latter modules.
The source implementation is in the repository's `src/` directory.

## FeedbackLoop

Construct with `{store, namespace, maximumPayloadBytes?, callbackTimeoutMs?,
sanitize?, clock?, deploymentsEnabled?}`. Required store version is 3; namespace
must be a non-empty string. Defaults: payload 262,144 bytes, callback 120,000 ms.

| Method | Contract |
| --- | --- |
| recordExecution(input) | Insert-only capture, idempotent identical caller ID |
| completeExecution(id,input,expectedRevision) | CAS output/metadata/completedAt update |
| recordSignal(input) | Insert-only scoped signal with verified-by-application source |
| getExecution(id), getCandidate(id) | Scoped reads, undefined if absent |
| list(collection,pageOptions) | Scoped page, default 100 / max 1,000 |
| analyze(options) | Bounded evidence snapshot and descriptive findings |
| createCandidate(input) | Immutable proposed content/evidence hashes |
| evaluateCandidate(id,context,evaluator) | Versioned callback; stale results discarded |
| `approveCandidate(id,{actor,evaluationId})` | Exact latest passing evaluation only |
| rejectCandidate(id,reason) | Explicit rejection from pre-deployment states |
| `deployCandidate(id,{adapter,expectedArtifactVersion?,signal?})` | Durable attempt and coordinated external application |
| `rollbackCandidate(id,{adapter,signal?})` | Reverse active version to explicit predecessor |
| reconcileAttempt(id,adapter,signal?) | Inspect pending outcome, never blindly replay |
| getActiveCandidate(target) | Current recorded active candidate, not a live provider inspection |
| deleteNamespace(confirmation) | Exact-name explicit deletion; coordinate stopped writers first |
| close() | Release store resources; PostgreSQL pool stays application-owned |

The client exposes its namespace/store for advanced integration. Direct store access
is trusted adapter-level access, not a way to bypass lifecycle invariants safely.
Do not manually alter targets/attempts/candidate states.

## Other exports

`ImprovementController(loop, {workflows, mode?, selfImproving?})` is the 0.3 durable
controller. Defaults are `mode: 'recommend'` and `selfImproving: false`. Automatic
approval/deployment requires both autonomous mode and the explicit flag, plus a valid
exact-target policy and all adapters. Methods: `tick(workflowId, signal?)`, `getRun(runId)`,
`listRuns(options?)`, `pause(workflowId, reason)`, and `resume(workflowId)`.
Applications own scheduling. See [autonomous improvement](/closing-the-loop/opt-in-autonomous-improvement).

The deprecated reviewed-only `SelfImprovementController(loop).run(input)` accepts analysis, policy, recipes and
optional evaluator/evaluation identity, deploymentAdapter and signal. The default
autonomy is recommend. See [controller policy](/closing-the-loop/governed-self-improvement).

`InMemoryStore()` and `JsonFileStore(path)` are development adapters.
`PostgresStore(pool)` and explicit `migratePostgres(pool)` implement the reference
database path. `runStoreConformance(store)` creates/deletes only random test namespaces.
`importLegacyV1(loop, document)` imports scoped executions/signals and archives old
candidate history without activation. See the repository migration guide.

`LoopiterError.code` includes invalid_input, invalid_store, conflict, not_found,
invalid_transition, integrity_error, namespace_mismatch, query_limit and timeout.
Deployment uncertainty exposes code deployment_pending and attemptId, with the
original cause retained. Do not classify all errors as retryable. A timeout may have
dispatched an external action; only inspection establishes the outcome.
