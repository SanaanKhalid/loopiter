<Warning>
The 0.3 alpha replaces automatic application with a durable, explicit opt-in
controller. `apply` and `experimentalAutoApply` are rejected, not translated into autonomy.
Follow the [new controller guide](/closing-the-loop/opt-in-autonomous-improvement).
This page retains the Node-only reviewed recipe API for migration.
</Warning>

The legacy controller coordinates trusted application callbacks; it does not invent a
training algorithm or discover reliable feedback by itself. A recipe has a name,
version, boolean `matches(finding, context)` and `propose(finding, context)` callback.
The latter returns zero, one or several JSON proposals. Supply an allowed-target list.

| Mode | Behavior |
| --- | --- |
| observe | Analyze only |
| recommend (default) | Store proposals; no evaluation, approval or deployment |
| experiment | Evaluate candidates; no automatic deployment |

Experiment is **not a sandbox**. Callbacks execute in your process with your
credentials. If they perform side effects, the SDK cannot prevent them. Separate
model/evaluator/deployment privileges and isolate untrusted code yourself.

## Budgets and cancellation

Defaults are three proposal calls and three candidates per run, a ten-minute run
deadline and a two-minute callback deadline. Budgets are checked before additional
expensive recipe callbacks. You may configure them explicitly; limits do not
automatically translate to a monetary/token budget. Bound provider requests too.

Callbacks receive `AbortSignal`. Cancellation/deadlines reject and discard late
results, but cannot forcibly stop arbitrary JavaScript or undo an external request.
A pending deployment remains reserved and needs reconciliation even if a run times out.
The application owns the run invocation/schedule; no background daemon is started.

## Migrating automatic application

The legacy controller no longer approves or deploys. Use a fresh `ImprovementController`
workflow with `mode: 'autonomous'`, `selfImproving: true`, exact target policy, persistent
budgets, separate validation/audit datasets and production observation. Legacy evaluations
and approvals do not grant autonomous authority. Start with `recommend` or `experiment`.

Constraints support gte/lte/gt/lt/eq with finite thresholds. They supplement, not
override, the evaluator's own passing result. Set `deploymentsEnabled: () => false`
on the client to stop new application; rollback and inspection remain available for
recovery. The switch cannot undo a previously dispatched operation.

Legacy results expose findings, candidates, proposalCalls, an empty deployed list and
structured `blocked` reasons such as evaluation_failed, target_not_allowed,
run_budget_reached and run_cancelled.
Forward these to your logger. Persisted lifecycle events can be paged separately.
Loopiter sends no telemetry. The new controller adds durable leases and target coordination;
neither controller provides hosted scheduling or a scheduling SLA.
